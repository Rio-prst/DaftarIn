                    PANDUAN LENGKAP KONFIGURASI DAN DEPLOYMENT
                                 DAFTARIN (2026)
================================================================================

Dokumen ini memuat panduan komprehensif implementasi, konfigurasi variabel
lingkungan (environment variables), dan arsitektur deployment aplikasi DaftarIn.
Seluruh nilai yang dicantumkan merupakan format referensi/placeholder. JANGAN
pernah memasukkan kredensial privat, secret key, atau password produksi ke dalam
laporan, log, atau repositori publik.

--------------------------------------------------------------------------------
1. IKHTISAR ARSITEKTUR DAN MODEL OPERASIONAL
--------------------------------------------------------------------------------

DaftarIn dirancang dengan arsitektur modern yang mendukung dua mode operasional:

A. Mode API Penuh (Integrated Production / Staging Mode)
   - Frontend berkomunikasi dengan REST API Backend NestJS.
   - Data tersimpan persisten di PostgreSQL (Prisma ORM).
   - Berkas warga tersimpan secara immutable di Supabase Storage (atau fallback lokal).
   - Mendukung autentikasi berbasis HttpOnly Cookie dan Bearer Token.
   - Seluruh siklus layanan (Warga -> Petugas Verifikasi -> Administrator) berjalan
     secara riil melalui transaksi basis data.

B. Mode Demo Lokal (Offline / Standalone Showcase Mode)
   - Diaktifkan melalui variabel: `VITE_AUTH_MODE=demo` pada Frontend.
   - Berjalan mandiri di browser menggunakan data simulasi dan penyimpanan lokal
     (localStorage / sessionStorage).
   - Cocok untuk presentasi juri atau evaluasi antarmuka tanpa ketergantungan
     pada server backend aktif.

--------------------------------------------------------------------------------
2. POLA TOPOLOGI DEPLOYMENT
--------------------------------------------------------------------------------

Tersedia dua opsi topologi deployment yang direkomendasikan:

--------------------------------------------------------------------------------
TOPOLOGI A: Single-Domain / Same-Origin via Reverse Proxy (Direkomendasikan VPS)
--------------------------------------------------------------------------------
Pada pola ini, Frontend dan Backend berada di bawah domain yang sama melalui
reverse proxy (Nginx, Traefik, atau Cloudflare Tunnel):
  - Frontend SPA  : https://daftarin.id/
  - Backend API   : https://daftarin.id/api/
  - Swagger Docs  : https://daftarin.id/api/docs

Keunggulan:
- Tidak ada isu pemblokiran cookie pihak ketiga (third-party cookie blocking)
  pada browser modern (Safari ITP, Chrome Privacy Sandbox).
- Konfigurasi CORS sederhana (`CORS_ORIGIN=https://daftarin.id`).
- Nilai `VITE_API_URL=/api` pada frontend bekerja langsung tanpa build ulang URL.

--------------------------------------------------------------------------------
TOPOLOGI B: Cross-Domain (Frontend di Vercel + Backend di Railway/Render/VPS)
--------------------------------------------------------------------------------
Pada pola ini, Frontend dan Backend di-host pada platform terpisah:
  - Frontend SPA  : https://daftarin.vercel.app (atau https://app.daftarin.id)
  - Backend API   : https://daftarin-api.up.railway.app (atau https://api.daftarin.id)

Pertimbangan Kritis:
1. HTTPS Wajib: Kedua domain HARUS menggunakan HTTPS valid.
2. CORS: Backend harus menyetel `CORS_ORIGIN=https://daftarin.vercel.app`
   dengan header `credentials: true`.
3. Cookie Sesi:
   - Jika menggunakan domain yang sepenuhnya berbeda (`vercel.app` vs `railway.app`),
     cookie lintas domain harus menggunakan `SameSite=None; Secure=true`.
   - Alternatif yang lebih andal: Menggunakan custom subdomain pada root domain yang
     sama (misal `app.daftarin.id` dan `api.daftarin.id`) dengan menyetel
     `COOKIE_DOMAIN=.daftarin.id`.
4. Fallback Bearer Token:
   - Backend `JwtAuthGuard` DaftarIn telah dilengkapi dukungan dual-mode:
     menerima cookie `access_token` DAN header `Authorization: Bearer <token>`.
     Hal ini memastikan otentikasi tetap berjalan lancar bahkan jika cookie
     terblokir oleh kebijakan privasi browser seluler.

3. MATRIKS VARIABEL LINGKUNGAN (ENVIRONMENT VARIABLES)
--------------------------------------------------------------------------------

A. FRONTEND (Vite / React)
File template: `frontend/.env.example`
Lokasi runtime: Di-inject pada saat build (`npm run build`) atau environment Vercel.

| Nama Variabel           | Tipe   | Contoh Nilai                   | Deskripsi & Catatan                                            |
|-------------------------|--------|--------------------------------|----------------------------------------------------------------|
| VITE_AUTH_MODE          | string | `api` atau `demo`              | Menentukan apakah aplikasi memanggil backend riil atau draf    |
|                         |        |                                | lokal mandiri.                                                 |
| VITE_API_URL            | string | `/api` atau                    | Basis URL endpoint REST API. Gunakan `/api` untuk local proxy  |
|                         |        | `https://api.daftarin.id/api`  | atau single-domain; URL absolut untuk cross-domain.            |

B. BACKEND (NestJS / Node.js)
File template: `backend/.env.example`
Lokasi runtime: Disetel pada `.env` lokal atau Dashboard Railway/Render/VPS.

| Nama Variabel                 | Tipe    | Contoh Nilai                           | Deskripsi & Catatan                                    |
|-------------------------------|---------|----------------------------------------|--------------------------------------------------------|
| NODE_ENV                      | string  | `production` atau `development`        | Mode runtime aplikasi.                                 |
| PORT                          | number  | `3000` (atau diset otomatis platform)  | Port listen HTTP server NestJS.                        |
| DATABASE_URL                  | string  | `postgresql://user:pass@host:5432/db`  | Koneksi runtime Prisma dengan connection pooling.      |
| DIRECT_URL                    | string  | `postgresql://user:pass@host:5432/db`  | Koneksi langsung tanpa pooler untuk Prisma migrations. |
| DATABASE_URL_TEST             | string  | `postgresql://.../test_db`             | Koneksi basis data terisolasi untuk suite tes otomatis.|
| SUPABASE_URL                  | string  | `https://<ref>.supabase.co`            | Endpoint API Supabase project.                         |
| SUPABASE_SERVICE_ROLE_KEY     | string  | `eyJh...`                              | Kunci rahasia Service Role (hanya di server backend).  |
| SUPABASE_STORAGE_BUCKET       | string  | `documents`                            | Nama bucket privat (Public: false) berkas warga.       |
| JWT_ACCESS_SECRET             | string  | `string-acak-panjang-min-32-karakter`  | Kunci enkripsi tanda tangan JWT access token.          |
| JWT_ACCESS_TTL                | string  | `15m`                                  | Masa aktif access token sebelum perlu refresh.         |
| REFRESH_TOKEN_TTL_DAYS        | number  | `7`                                    | Masa aktif refresh token (disimpan dalam bentuk hash). |
| COOKIE_SECURE                 | boolean | `true` (produksi) / `false` (lokal)    | Wajib `true` untuk HTTPS agar cookie tidak ditolak.    |
| COOKIE_DOMAIN                 | string  | `.daftarin.id` atau kosong             | Domain cookie (kosongkan jika cross-origin total).     |
| CORS_ORIGIN                   | string  | `https://daftarin.id` (multi via koma) | Alamat domain frontend yang diperbolehkan mengakses.   |
| REDIS_URL                     | string  | `redis://localhost:6379`               | URL Redis untuk antrian pemrosesan tugas latar (opsi). |
| INSPECTION_QUEUE_CONCURRENCY  | number  | `2`                                    | Jumlah worker antrian paralel.                         |
| AI_PROVIDER                   | string  | `disabled`                             | Provider verifikasi AI berkas (disabled pada versi ini)|
| OCR_PROVIDER                  | string  | `disabled`                             | Provider ekstraksi OCR (disabled pada versi ini).      |
| MAX_UPLOAD_BYTES              | number  | `10485760`                             | Batas ukuran berkas (10 MB). Diselaraskan FE & BE.     |
| MAX_PDF_PAGES                 | number  | `20`                                   | Batas jumlah halaman PDF.                              |
| SWAGGER_ENABLED               | boolean | `true` atau `false`                    | Menampilkan dokumentasi OpenAPI pada `/api/docs`.      |
| CHAT_AI_PROVIDER              | string  | `gemini` atau `openai` atau `disabled` | Provider model bahasa chatbot publik warga.            |
| CHAT_AI_API_KEY               | string  | `kunci-api-asisten`                    | API key penyedia AI chatbot publik.                    |
| CHAT_AI_MODEL                 | string  | `gpt-4o-mini` / `gemini-1.5-flash`     | Nama model chatbot panduan.                            |

4. PROSEDUR DEPLOYMENT PRODUKSI LANGKAH-DEMI-LANGKAH
--------------------------------------------------------------------------------

LANGKAH 1: Persiapan Basis Data (PostgreSQL)
1. Buat instance PostgreSQL baru di Supabase, Neon, Railway, atau VPS.
2. Dapatkan connection string:
   - Pooling mode (Port 5432/6543) untuk `DATABASE_URL`.
   - Direct connection mode (Port 5432) untuk `DIRECT_URL`.
3. Jalankan migrasi skema resmi:
   ```bash
   cd backend
   npx prisma migrate deploy
   ```
4. Jalankan inisialisasi akun contoh dan katalog layanan (Idempotent):
   ```bash
   npm run demo:bootstrap
   ```
   Script ini secara aman memastikan peran (`citizen`, `officer`, `admin`),
   akun default, dan katalog layanan siap tanpa menghapus data atau membuat
   pengajuan otomatis.

LANGKAH 2: Persiapan Storage Berkas (Supabase Storage)
1. Buat bucket baru bernama `documents` di Dashboard Supabase Storage.
2. Pastikan status bucket adalah **PRIVATE** (Public: false).
3. Buat Access Policy agar hanya `service_role` yang dapat membaca/menulis:
   - DaftarIn mengakses berkas melalui URL bertanda tangan (signed URL) atau
     endpoint proxy backend (`/api/storage/raw`), sehingga berkas warga terlindungi
     dari akses publik langsung.
   - Jika Supabase Storage tidak diisi, backend secara otomatis beralih ke
     penyimpanan lokal (`storage_files/`).

LANGKAH 3: Deployment Backend (Node.js / Docker)
1. Tentukan environment variables sesuai tabel Section 3 di atas.
2. Build aplikasi:
   ```bash
   npm run build
   ```
3. Jalankan daemon aplikasi:
   ```bash
   npm run start:prod
   ```
4. Verifikasi kesehatan API:
   ```bash
   curl -i https://your-backend-domain.com/api/health
   ```
   Harus menghasilkan: `{"data":{"status":"ok"}}`.

LANGKAH 4: Deployment Frontend (Vite Static Hosting)
1. Masukkan environment variable pada platform hosting (misal: Vercel):
   ```env
   VITE_AUTH_MODE=api
   VITE_API_URL=https://your-backend-domain.com/api
   ```
2. Build dan deploy:
   ```bash
   npm run build
   ```
3. Uji alur dari browser:
   - Login warga (`warga@daftarin.test` / `DaftarIn2026!`).
   - Buat persiapan dan kirim berkas ke petugas.
   - Login petugas (`petugas@daftarin.test` / `DaftarIn2026!`).
   - Verifikasi antrean, minta perbaikan, atau setujui berkas.
