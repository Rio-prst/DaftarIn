1. PRIORITAS SEKARANG: SUPABASE STORAGE
Status: branch feat/backend terbaru (a56a80e) sudah memiliki adapter upload,
versi dokumen dan signed URL privat. Belum digabung ke frontend lokal;
konfigurasi dan koneksi Storage tim belum diverifikasi.

Yang perlu disiapkan:
- SUPABASE_URL: Project URL, misalnya https://<project-ref>.supabase.co.
- Key server: template lokal memakai SUPABASE_SECRET_KEY (sb_secret_...).
  Jika tim masih memakai legacy service_role key, cukup sediakan salah satu
  key server yang sesuai. Tidak perlu menyerahkan kedua jenis key.
  StorageService terbaru membaca SUPABASE_SERVICE_ROLE_KEY. Selaraskan nama
  variabel dengan implementasi sebelum menjalankan server.
- SUPABASE_STORAGE_BUCKET: nama bucket privat, misalnya documents-dev.

Tempat mengambil:
- Buka project Supabase. Project URL ada pada dialog Connect.
- Key server ada di Settings > API Keys. Pilih secret key untuk backend;
  publishable/anon key saja tidak menggantikannya pada rancangan ini.
- Buat/pilih bucket pada menu Storage. Untuk berkas warga, Public harus OFF.

Pengaturan aplikasi yang direncanakan:
- Browser mengakses backend; backend memeriksa pemilik/penugasan petugas,
  kemudian membaca atau menyimpan berkas melalui Supabase Storage.
- Secret key melewati RLS, jadi pemeriksaan akses oleh backend wajib ada.
- Secret tidak boleh berada pada frontend, variabel VITE_*, atau GitHub.
- Supabase Storage bukan Supabase Auth. Akun sekarang memakai auth NestJS;
  memilih Storage ini tidak otomatis mengaktifkan login/reset email Supabase.
- Tidak perlu R2 Account ID, R2 endpoint, R2 token, atau kredensial S3
  tersendiri untuk pendekatan Supabase JS SDK ini.
- Mengisi key saja belum membuat upload aplikasi otomatis terhubung.
