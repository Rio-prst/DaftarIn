--------------------------------------------------------------------------------

(React + Vite) dan REST API Backend (NestJS + Prisma + PostgreSQL). Seluruh alur

2. CAKUPAN INTEGRASI MODUL BISNIS YANG DISELESAIKAN
--------------------------------------------------------------------------------

A. Autentikasi, Keamanan Sesi, dan Profil Warga
   - Endpoint: `POST /api/auth/login`, `POST /api/auth/register`, `POST /api/auth/logout`,
     `GET /api/account`, `POST /api/account/password`, `GET/PATCH /api/account/preferences`.
   - Bug Ubah Sandi: Terselesaikan sepenuhnya. Pengubahan kata sandi secara aman
     menghapus refresh session lama, mengupdate hash password baru dengan bcrypt (salt 12),
     dan menolak kata sandi lama.
   - Dual-Mode Token: Guard `JwtAuthGuard` backend mendukung ekstraksi cookie HttpOnly
     `access_token` serta header `Authorization: Bearer <token>`, memberikan ketahanan
     maksimal terhadap pembatasan third-party cookie pada browser modern.

B. Pengelolaan Data Anggota Keluarga Warga
   - Endpoint: `GET /api/account/family-members`, `POST /api/account/family-members`,
     `GET /api/account/family-members/:id`, `PATCH /api/account/family-members/:id`,
     `DELETE /api/account/family-members/:id`.
   - Terhubung langsung ke tabel `family_members` di database. Data keluarga yang
     disimpan dapat dipilih saat warga mengisi persiapan layanan.

C. Layanan Bantuan dan Klarifikasi Warga (Help Desk)
   - Endpoint: `GET /api/help-requests`, `POST /api/help-requests`,
     `GET /api/help-requests/:id`, `POST /api/help-requests/:id/replies`.
   - Warga dapat mengajukan pertanyaan/kendala pengurusan formulir dan menerima
     balasan atau catatan klarifikasi secara persisten di database.

D. Pusat Notifikasi Terpadu
   - Endpoint: `GET /api/notifications`, `POST /api/notifications/read-all`,
     `PATCH /api/notifications/:id/read`.
   - Query pagination dan listing dioptimalkan secara sequential (`findMany` lalu `count`),
     menjamin stabilitas koneksi driver adapter PostgreSQL.

E. Persiapan Layanan, Data Pemohon, dan Unggahan Berkas
   - Endpoint: `GET /api/services`, `POST /api/preparations`, `PATCH /api/preparations/:id`,
     `POST /api/documents/upload`, `GET /api/documents/:id`.
   - Berkas diunggah dengan batas ukuran 10 MB (diselaraskan antara FE dan BE).
   - Pengunggahan dokumen ke Supabase Storage (atau fallback folder `storage_files/`)
     menggunakan kebijakan strictly immutable (`upsert: false`), menjamin versi berkas
     tidak pernah saling menimpa secara tidak sengaja.

F. Pengiriman Permohonan dan Snapshot Tetap (Immutable Snapshot)
   - Endpoint: `POST /api/preparations/:id/submissions`.
   - Saat warga menekan "Kirim ke Petugas", aplikasi membekukan kondisi formulir
     dan dokumen menjadi `submission_snapshots` versi 1.
   - Perubahan berikutnya pada draf persiapan warga TIDAK akan mengubah berkas yang
     sedang diperiksa petugas pada snapshot aktif.

G. Penugasan Petugas & Pencabutan Akses Tugas Lama (Admin Reassignment)
   - Endpoint: `POST /api/admin/assignments`.
   - Logika Backend: Pembuatan penugasan petugas baru secara otomatis mencabut
     penugasan petugas sebelumnya dengan status `assignmentStatus: 'REVOKED'` dan
     mencatat timestamp `endedAt: new Date()`.
   - Riwayat penugasan tetap tersimpan lengkap di audit trail tanpa konflik hak akses.

H. Peninjauan Petugas, Catatan Per Butir, dan Permintaan Revisi
   - Endpoint: `GET /api/officer/assignments`, `POST /api/officer/applications/:id/events`,
     `POST /api/officer/applications/:id/decisions`.
   - Petugas dapat memulai peninjauan (`status_changed: verification`), menilai dokumen
     per butir (`item_assessments`), dan menerbitkan keputusan permintaan revisi
     (`decision: revision_requested`) lengkap dengan arahan perbaikan terstruktur.

I. Pengiriman Ulang Revisi Warga pada Permohonan yang Sama
   - Endpoint: `POST /api/applications/:id/resubmissions`.
   - Warga mengirim berkas pengganti tanpa membuat aplikasi baru dari nol.
   - Sistem secara otomatis membentuk `submission_snapshots` versi 2 yang terikat
     pada `applicationId` yang sama, sehingga riwayat perbaikan utuh dan transparan.

J. Persetujuan Akhir Petugas Tinjauan
   - Endpoint: `POST /api/officer/applications/:id/decisions`.
   - Petugas menyelesaikan peninjauan dengan keputusan `approved_for_submission`,
     memberikan kepastian kepada warga bahwa berkas telah lengkap dan siap diajukan
     ke loket fisik instansi atau kanal resmi pemerintah.

K. Catatan Tindak Lanjut Warga & Konfirmasi Penerimaan Hasil Resmi
   - Endpoint: `POST /api/applications/:id/citizen-notes`,
     `POST /api/applications/:id/confirm-result-received`.
   - Warga mencatat tanggal penyerahan ke loket dan nomor tanda terima resmi instansi.
   - Setelah dokumen fisik diterbitkan oleh instansi, warga mengonfirmasi penerimaan hasil
     sehingga status pengajuan berubah menjadi `RESULT_RECEIVED_BY_CITIZEN`.
   - Penarikan pengajuan (`withdrawReview`) dicegah secara otomatis jika hasil telah diterima.

L. Garis Waktu Pengajuan (Timeline Status Events)
   - Endpoint: `GET /api/applications/:id/timeline`.
   - Menyajikan 7 jejak rekam transparan: pengiriman awal, penugasan petugas, mulai verifikasi,
     permintaan revisi, pengiriman revisi v2, catatan warga, dan konfirmasi penerimaan hasil.

5. PANDUAN PENYIAPAN LINGKUNGAN (ENVIRONMENT & DEPLOYMENT)
--------------------------------------------------------------------------------
File dokumentasi lengkap telah dibuat pada: `ENV-DEPLOYMENT.txt` di root repository.
File template variabel lingkungan bersih tanpa rahasia telah disiapkan:
  - `backend/.env.example`
  - `frontend/.env.example`

Ringkasan parameter deployment:
1. Vercel (Frontend):
   - Setel `VITE_AUTH_MODE=api`
   - Setel `VITE_API_URL=https://<domain-backend>/api`
2. Railway / VPS (Backend):
   - Setel `NODE_ENV=production`
   - Setel `COOKIE_SECURE=true` (untuk domain ber-HTTPS)
   - Setel `CORS_ORIGIN=https://<domain-frontend>`
   - Hubungkan `DATABASE_URL` dan `DIRECT_URL` ke PostgreSQL.
   - Jalankan `npx prisma migrate deploy` lalu `npm run demo:bootstrap`.
