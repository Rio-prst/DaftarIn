2. ANALISIS AKAR MASALAH BUG SANDI & PERBAIKANNYA
--------------------------------------------------------------------------------
Gejala yang dialami sebelumnya:
- Pengguna mengubah kata sandi dan melihat pesan berhasil.
- Setelah keluar/refresh, login dengan sandi baru gagal.
- Login dengan sandi lama juga gagal.

Akar Masalah yang Ditemukan:
a. Race Condition Navigasi URL & RequireAuth:
   Di AuthContext.tsx, changePassword memanggil setUser(null). Saat user menjadi
   null ketika pengguna berada di rute /akun, komponen RequireAuth langsung
   merender <Navigate to="/masuk?next=%2Fakun" replace />. Ini menimpa navigasi
   yang diarahkan ke /masuk?password_changed=1. Akibatnya, parameter query
   password_changed dan email hilang, banner sukses tidak muncul, dan field email
   menjadi kosong.
b. Jebakan "Coba Akun Contoh" di LoginPage:
   Ketika penguji kembali ke halaman masuk, pengguna sering menekan tombol cepat
   "Coba akun contoh" -> "Warga" (Ayu Contoh). Tombol ini memiliki kode statis yang
   mengisikan EXAMPLE_PASSWORD ("DaftarIn2026!"). Karena sandi Ayu baru saja diubah
   dan credential PBKDF2 tersimpan di localStorage, sandi default tersebut ditolak
   ("Sandi lama gagal").
c. Penghapusan Akun Otomatis pada Multi-tab / Reload (demoBootstrap.ts):
   prepareCleanLocalDemo() pada demoBootstrap.ts sebelumnya menghapus seluruh kunci
   localStorage yang berawalan "daftarin:" jika RESET_KEY belum "done". Ini secara
   tidak sengaja menghapus akun warga baru yang baru saja didaftarkan serta
   menghapus kredensial sandi baru akun contoh kembali ke fixture awal.
d. Kurangnya Persetujuan Otomatis pada Helper Pendaftaran (RegisterPage.tsx):
   Tombol "Isi data contoh" di pendaftaran tidak mengaktifkan checkbox persetujuan
   (consent), sehingga pengiriman formulir tertahan oleh validasi.

Perbaikan yang Diterapkan:
1. AuthContext.tsx:
   Menyimpan email pengguna sebelum logout dan menavigasi secara eksplisit ke
   `/masuk?password_changed=1&email=${encodeURIComponent(targetEmail)}` dengan replace,
   sebelum membersihkan user state.
2. RequireAuth.tsx:
   Memeriksa apakah parameter `password_changed=1` ada di URL; jika ada, parameter
   tersebut dipertahankan dan tidak ditimpa oleh `?next=%2Fakun`.
3. LoginPage.tsx:
   - Secara otomatis mengisi field NIK/Email dari parameter URL dan memfokuskan
     kursor ke field kata sandi baru.
   - Pada bagian "Coba akun contoh", sistem memeriksa apakah akun memiliki
     kredensial sandi baru (isCustomCredential). Jika sandi sudah diubah, sistem
     menampilkan label "(sandi baru)" dan TIDAK mengisikan sandi lama, melainkan
     memfokuskan pengguna untuk mengetikkan sandi barunya.
   - Menambahkan proteksi mode API agar pengguna diingatkan menggunakan email, bukan NIK.
4. demoBootstrap.ts:
   Fungsi reset demo sekarang mempertahankan kunci `daftarin:accounts:v1`. Akun yang
   didaftarkan dan sandi yang diubah tidak lagi terhapus secara sepihak saat halaman
   dimuat ulang atau dibuka di tab baru.
5. mockAuth.ts:
   Memperbaiki `readAccounts()` agar aman terhadap array kosong dan tidak memfilter
   keluar akun petugas yang tidak memiliki NIK/telepon.
6. RegisterPage.tsx:
   Helper "Isi data contoh" kini otomatis mencentang persetujuan sehingga alur
   pendaftaran akun warga baru dapat langsung diuji.

4. PENYELARASAN KONFIGURASI LINGKUNGAN
--------------------------------------------------------------------------------
- Origin & Port:
  Frontend (Vite): http://127.0.0.1:5174 (dan 5173/5175)
  Backend (NestJS): http://127.0.0.1:3000
  Format alamat menggunakan 127.0.0.1 secara konsisten (tidak mencampur localhost).
- CORS:
  CORS_ORIGIN di backend/.env diselaraskan menjadi:
  `http://127.0.0.1:5173,http://127.0.0.1:5174,http://127.0.0.1:5175`
- Cookie Autentikasi:
  `access_token` dan `refresh_token` memakai `httpOnly: true`, `sameSite: 'lax'`,
  `secure: false` (lingkungan dev), dengan domain host-only (kosong).
- Batas Berkas (Upload Limit):
  Frontend: `MAX_UPLOAD_FILE_BYTES = 10 * 1024 * 1024` (10 MB).
  Backend: `MAX_UPLOAD_BYTES = 10485760` (10 MB).
- Database Safety:
  DATABASE_URL_TEST tidak dijalankan untuk migrasi atau seed otomatis karena
  mengarah ke target database yang sama.
- Keamanan Secret:
  File backend/.env dan frontend/.env lokal TIDAK dimasukkan ke dalam commit Git.
  File .env.example di kedua folder hanya memuat placeholder aman.

6. PANDUAN MENJALANKAN & DEMO LINTAS PERAN
--------------------------------------------------------------------------------
Langkah Menjalankan Backend:
1. Buka terminal di folder `backend`.
2. Jalankan: `npm run build`
3. Jalankan: `node dist/main.js` (Server aktif di http://127.0.0.1:3000).

Langkah Menjalankan Frontend:
1. Buka terminal di folder `frontend`.
2. Jalankan: `npm run dev -- --host 127.0.0.1 --port 5174`
3. Buka browser di http://127.0.0.1:5174.

Demo Alur Produk:
1. Warga:
   - Buka Beranda -> Cari Layanan (misal Penerbitan Kartu Keluarga).
   - Tentukan Kebutuhan (misal: Pisah KK setelah menikah).
   - Lengkapi formulir Data Pemohon dan simpan draf.
   - Unggah Dokumen (KTP, Buku Nikah, KK lama) dengan pratinjau hingga 10 MB.
   - Ajukan Tinjauan ke Petugas.
2. Petugas:
   - Masuk sebagai petugas (petugas@daftarin.test / DaftarIn2026!).
   - Buka Ruang Kerja Petugas -> Antrean Pengajuan.
   - Buka berkas permohonan, lakukan penilaian berkas (Sesuai / Perlu Perbaikan).
   - Kirim hasil tinjauan kepada warga.
3. Warga (Perbaikan & Selesai):
   - Warga menerima notifikasi perbaikan.
   - Warga memperbaiki dokumen tanpa mengubah nomor pengajuan.
   - Petugas menyetujui kesiapan berkas pendamping.
   - Warga mencatat tanda terima resmi setelah mengajukan ke kanal resmi Dukcapil.
4. Keamanan Akun:
   - Buka Akun saya > Keamanan.
   - Ganti kata sandi. Masuk kembali menggunakan sandi baru.
