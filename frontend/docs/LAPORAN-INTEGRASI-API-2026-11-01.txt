1. YANG SUDAH TERHUBUNG KE SERVER
- Registrasi nama/email/kata sandi, persetujuan privasi versi 2026-11-01.
  Pembuatan akun, peran warga, dan persetujuan berada dalam satu transaksi.
- Registrasi server mengarahkan ke halaman masuk; tidak membuat sesi palsu.
- Login, pemulihan sesi lewat refresh, logout, dan pengecekan peran.
- Token berada pada cookie HttpOnly, tidak ditulis ke localStorage.
- Pengaturan profil: nama, telepon, email baca-saja, dan deteksi konflik edit.
- Ganti kata sandi: validasi sandi lama dan pencabutan seluruh sesi.
- Daftar sesi masuk dan pencabutan sesi lain milik pengguna sendiri.
- Preferensi ukuran teks, kontras, dan pilihan notifikasi tersimpan per akun.
  Pilihan notifikasi belum berarti pengiriman notifikasi sudah diintegrasikan.
- Admin: pencarian akun, pagination, perubahan peran warga/petugas,
  penugasan instansi, penonaktifan akun, serta riwayat perubahan dari server.
- Perubahan akses admin memerlukan sandi admin, versi data terbaru, dan
  instansi aktif jika perannya petugas. Seluruh sesi target dicabut.
- Akses administrator tidak dapat diberikan lewat registrasi atau menu ini.
  Menu juga menolak perubahan akun sendiri dan akun admin lain.
- Penyediaan admin pertama menggunakan skrip operator, tanpa sandi bawaan.
- Mode API tidak menjalankan tombol manajemen akun/panduan lokal seolah-olah
  perubahan tersebut sudah disimpan ke server.

4. PENGAMAN YANG DITERAPKAN
- API gagal menampilkan error; tidak berganti diam-diam ke akun demo.
- JWT diperiksa terhadap sesi database, masa berlaku peran, dan status akun.
  Sesi yang dicabut tidak tetap lolos hanya karena JWT belum kedaluwarsa.
- Refresh token disimpan sebagai hash dan dirotasi. Replay token hasil
  rotasi mencabut sesi; token yang sengaja dicabut tidak memutus sesi lain.
- Refresh serentak dibatasi lewat single-flight dan Web Locks antar-tab.
- Hasil pengecekan sesi lama diabaikan setelah login/logout/ganti sandi.
- Konflik edit menghasilkan 409; perubahan akses dan audit bersifat atomik.
- Login terakhir tidak mengubah versi profil, sehingga login dari perangkat
  lain tidak menyebabkan konflik edit profil/akses yang tidak diperlukan.
- Produksi menolak konfigurasi cookie tidak Secure atau origin non-HTTPS.
- Logging error server hanya memuat request ID, jenis/kode error; tidak
  mencetak isi formulir, kata sandi, token, atau query database.
- Berkas env privat, database uji, node_modules, build, dan keluaran QA
  tetap diabaikan Git. Kredensial tidak dimasukkan pada laporan ini.

5. MIGRASI DAN MENJALANKAN
Backend: pnpm install --frozen-lockfile; siapkan .env di mesin backend;
kemudian pnpm exec prisma generate; pnpm exec prisma migrate deploy;
pnpm run build; pnpm run start:prod.
Migrasi tambahan: 202611010002_account_preferences.
Jangan menjalankan migrate reset pada database tim.
Untuk admin baru, operator mengisi ADMIN_EMAIL, ADMIN_NAME, ADMIN_PASSWORD
pada environment sementara, lalu menjalankan pnpm run account:create-admin.
Skrip menolak email yang sudah ada dan tidak menaikkan peran diam-diam.

Frontend: npm ci; gunakan VITE_AUTH_MODE=api dan VITE_API_URL=/api.
Vite development meneruskan /api ke backend 127.0.0.1:3000.
Produksi harus menyediakan reverse proxy /api ke backend; proxy Vite tidak
ikut dibawa ke hasil build. Jangan menaruh secret pada variabel VITE_*.
Mode demo tetap tersedia dengan VITE_AUTH_MODE=demo.
Sesi akun demo dan akun API adalah dua sistem yang berbeda.

7. ENAM SKENARIO UJI MANUAL
1) Daftar warga mode API dengan persetujuan. Akun tersimpan pada server,
   lalu masuk dari browser lain dengan email/sandi yang sama.
2) Ubah nama/telepon dan pengaturan tampilan. Muat ulang serta buka dari
   sesi kedua; perubahan tetap ada dan tidak mengubah akun berbeda.
3) Buka pengaturan keamanan, cabut sesi kedua. Permintaan privat dari sesi
   kedua ditolak; sesi utama masih berfungsi.
4) Coba ganti sandi dengan sandi lama yang salah, lalu yang benar. Setelah
   berhasil, semua sesi berakhir. Sandi lama ditolak, sandi baru dapat masuk.
5) Masuk admin yang dibuat operator. Cari akun warga, beri akses petugas
   pada instansi aktif, lalu nonaktifkan. Sesi target langsung ditolak;
   perubahan muncul pada riwayat server.
6) Masuk warga/pengunjung dan coba URL/endpoint admin. Akses ditolak.
   Coba dua editor admin pada akun yang sama; editor versi lama mendapat
   konflik dan perlu memuat ulang. Ulangi tampilan pada HP dan keyboard.

8. KEBUTUHAN INTEGRASI BERIKUTNYA
A. Pemilik PostgreSQL: URL runtime dan migrasi yang sesuai, persetujuan
   migrasi, serta data awal wilayah/instansi/panduan yang benar.
B. R2 privat: endpoint/account ID, bucket, access key, secret key dengan izin
   minimum. Upload dan download harus melalui backend serta pemeriksaan
   pemilik/penugasan petugas; jangan gunakan URL publik untuk dokumen warga.
C. Email transaksional: penyedia pengirim, domain terverifikasi, dan callback
   URL untuk verifikasi/pemulihan. Belum berpura-pura mengirim email.
D. LLM pihak ketiga: base URL, format API, nama model, batas token/biaya dan
   kebijakan data. Secret hanya di backend; chatbot tetap pendamping dengan
   tombol navigasi dan tanpa wewenang mengirim/mengubah permohonan sendiri.
E. Deployment: origin HTTPS, reverse proxy /api, secret sesi, backup,
   pemantauan error, retensi dan prosedur permintaan penghapusan data.
Kredensial dapat diisi nanti di environment pemilik; tidak perlu dikirim
sekarang untuk melanjutkan penyusunan modul bisnis dan kontrak API.
