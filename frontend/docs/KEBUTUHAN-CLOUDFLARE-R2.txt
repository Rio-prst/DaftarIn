KEBUTUHAN CLOUDFLARE R2 UNTUK DAFTARIN
======================================
Tanggal: 1 November 2026

Dokumen ini khusus kebutuhan R2, bukan daftar seluruh API aplikasi.
R2 akan menyimpan berkas warga pada bucket privat. Koneksi dilakukan
oleh backend NestJS; pengguna tidak perlu diberi akses dashboard Cloudflare.
Integrasi R2 belum diimplementasikan. Nama variabel berikut adalah usulan
konfigurasi untuk adapter yang akan dibuat, belum otomatis dibaca aplikasi.

1. DATA KONEKSI YANG PERLU DISIAPKAN

R2_ACCOUNT_ID
Account ID Cloudflare pemilik bucket.

R2_ENDPOINT
S3 API endpoint dari dashboard R2. Endpoint umum:
https://<ACCOUNT_ID>.r2.cloudflarestorage.com
Salin endpoint yang sesuai dari dashboard, terutama jika bucket menggunakan
jurisdiction khusus. Ini bukan alamat publik untuk membuka dokumen.

R2_BUCKET_NAME
Nama bucket yang akan dipakai, misalnya daftarin-documents-dev.
Bucket sebaiknya khusus aplikasi ini; pisahkan development dan produksi.

R2_ACCESS_KEY_ID
Access Key ID dari token R2 untuk mengakses objek dalam bucket tersebut.

R2_SECRET_ACCESS_KEY
Pasangan Secret Access Key. Simpan saat token dibuat karena nilainya
tidak dapat ditampilkan kembali oleh Cloudflare setelah tahap tersebut.

R2_REGION
Nilai untuk konfigurasi AWS SDK: auto.
Ini bukan instruksi untuk memindahkan lokasi penyimpanan bucket.

Template konfigurasi backend, semua masih placeholder:

R2_ACCOUNT_ID=<account-id>
R2_ENDPOINT=<s3-api-endpoint-dari-dashboard>
R2_BUCKET_NAME=<nama-bucket>
R2_ACCESS_KEY_ID=<access-key-id>
R2_SECRET_ACCESS_KEY=<secret-access-key>
R2_REGION=auto

Account ID, endpoint, dan nama bucket bukan secret login. Access Key ID
dan terutama Secret Access Key tetap disimpan sebagai kredensial backend.
Isi nilai asli di environment backend atau secret manager, bukan di file
laporan ini, frontend, variabel VITE_*, atau commit Git.

2. PENGATURAN YANG PERLU DIBUAT DI CLOUDFLARE

- Pastikan layanan R2 sudah aktif dan bucket sudah dibuat.
- Pada halaman R2, buka pengelolaan API Tokens dan buat token khusus aplikasi.
- Pilih izin Object Read & Write, dibatasi hanya pada bucket DaftarIn.
  Izin objek tersebut mencakup operasi baca/tulis/hapus objek; tidak perlu
  memberikan izin administrasi seluruh bucket atau seluruh akun.
- Catat Access Key ID, Secret Access Key, dan S3 API endpoint yang diberikan.
- Untuk dokumen warga, jangan aktifkan public access melalui r2.dev ataupun
  custom domain publik pada bucket tersebut.

Tidak perlu memberikan password akun Cloudflare, Global API Key,
akses DNS/domain, atau akses penuh dashboard untuk integrasi S3 ini.
Yang dipakai SDK adalah pasangan Access Key ID dan Secret Access Key R2,
bukan sembarang Bearer API token Cloudflare.

3. DEPENDENCY KODE BACKEND

Wajib untuk pendekatan backend Node.js yang direncanakan:
@aws-sdk/client-s3

Perintah pemasangan nanti, dari folder backend:
pnpm add @aws-sdk/client-s3

Package ini menyediakan koneksi S3-compatible serta operasi upload,
baca, pemeriksaan metadata, dan penghapusan objek di R2.

Opsional jika nanti dipilih akses melalui tautan bertanda tangan:
@aws-sdk/s3-request-presigner

Perintah pemasangan hanya jika pendekatan itu dipakai:
pnpm add @aws-sdk/s3-request-presigner

Untuk rencana awal upload/download melalui backend, presigner tidak wajib.
Tidak perlu memasang dependency R2 pada frontend. Backend tetap berjalan
pada Node.js/NestJS; penggunaan R2 tidak mengharuskan pindah ke Workers,
memasang Wrangler, atau memakai Cloudflare Pages.

4. ALUR INTEGRASI YANG AKAN DIBUAT

Warga masuk -> backend memeriksa pemilik persiapan dan file -> backend
mengunggah ke R2 -> database mencatat object key, pemilik, ukuran, jenis,
serta versi dokumen.

Saat warga/petugas membuka berkas, backend memeriksa sesi dan hak akses
terlebih dahulu. Petugas hanya boleh mengakses berkas yang terkait dengan
penugasan peninjauannya. Baru setelah itu backend mengambil isi dari R2.
Mengetahui nama file atau object key saja tidak memberikan hak akses.

Database tetap dibutuhkan untuk data pemilik, versi, dan penugasan.
R2 menyimpan isi berkas; R2 tidak menggantikan PostgreSQL.

CORS bucket tidak diperlukan untuk alur browser -> backend -> R2 ini.
Jika nanti browser mengunggah langsung ke R2 menggunakan presigned URL,
baru diperlukan CORS bucket untuk origin, metode, dan header yang dipakai.
Bucket tetap privat walaupun memakai presigned URL. URL tersebut harus
singkat masa berlakunya dan baru diterbitkan setelah pemeriksaan akses.

5. YANG BELUM PERLU DISEDIAKAN UNTUK R2

- Domain publik/CDN khusus dokumen warga.
- Cloudflare Workers atau Pages.
- Cloudflare Images, Stream, maupun layanan AI Cloudflare.
- API key Claude atau token LLM.
- Supabase Storage service-role key jika penyimpanan berkas memakai R2.
